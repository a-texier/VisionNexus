Innovations techniques clés

// ByteTrack
BYTE - associer toutes les boîtes, même faible confiance
2 passes - haute conf. d'abord, puis basses vs tracklets perdus
Kalman standard - état = (x, y, a, h) + vélocités
Pas de ReID - IoU seul pour l'association
Post-proc. - interpolation linéaire des tracklets manquants
// BOT-SORT
Kalman modifié - état = (x, y, w, h) au lieu du ratio d'aspect
GMC - compensation globale mouvement caméra (ECC/ORB)
Fusion IoU+ReID - min(dist_IoU, dist_cosine) comme coût
Rejet cosine - seuil sur la similarité d'apparence
FastReID - réseau léger d'embeddings (optionnel)
// BoostTrack++
Score conf. DT - pondère la similarité détection-tracklet
Mahalanobis - lève les ambiguïtés que l'IoU ne résout pas
Similarité de forme - pénalise les changements de ratio w/h
Boost confiance - rehausse les détections faibles pertinentes
Association 1 passe - toutes les mesures fusionnées

Single Object Tracking - initialisation par clic
L'utilisateur clique une fois sur la cible (ou dessine une bbox) pour initialiser le tracker - pas de détecteur externe nécessaire. Le tracker apprend l'apparence de la cible à partir de ce seul exemple et la suit frame par frame. Cas typiques : suivre P0 dans un pipeline MOT hybride, annotateur vidéo, suivi d'acteur, drone FPV. Trois familles coexistent : trackers classiques sans IA, réseaux siamois CNN, et modèles de fondation récents basés transformers.
Classique - sans apprentissage profond
Filtres de corrélation, sans GPU, ultra-légers. Idéal embarqué / temps réel contraint.

↔ Pont SOT / MOT - Pipeline hybride (P0 + multi-objets)
Mode pur SOT
Clic sur P0 -> tracker SOT suit la cible unique
Les autres objets ignorés
Idéal : CSRT (CPU) ou SAM 2 (GPU, masque)
Pas de détecteur, init one-shot
Mode SOT + MOT hybride
Clic -> SOT initialise l'ID de la cible prioritaire P0
MOT tourne en parallèle pour les autres
La cible est réidentifiée via ReID si perdue
Ex : ByteTrack + SAM 2 pour P0
Mode fondation zéro-shot
Clic ou texte -> Grounded-SAM 2 / DEVA
Suit tous les objets de la classe décrite
Pas de fine-tuning, pas de dataset custom
Coût élevé : 12 GB GPU minimum

VisionNexus Pipeline — Architecture et flux
Orchestration frame-par-frame : loader optional_format/PNG → detecteur YOLO → compensation ego-motion → state machine MOT/SOT → visualiseur. Un fichier cmd_send.txt pilote les transitions (mode command), ou la souris en mode interactive. Le mode headless produit video et metriques sans interface.

Flux de donnees (boucle principale)

SequenceLoader         optional_format (MultiCsv) | ImageFolder (PNG/JPG)
      |  frame brute (IR uint16 normalise en BGR uint8)
      v
YOLODetector           weights/last.pt  ->  raw_dets[]  [x1,y1,x2,y2,score]
      |
      |  EgoMotionCompensator   H_ldv (LDV inertiels) | H_image (ORB/ECC fallback)
      v
comp_dets[]                     detections compensees ego-motion
      |
      +--- CommandParser     cmd_send.txt   (mode command)
      |         |                   3 champs  ->  MotControlCommand  ->  set_mot_active()
      |         |                   4 champs  ->  ClickCommand       ->  trigger_sot()
      +--- ClickHandler      clic souris    (mode interactive)
      |
      v
TrackerStateMachine
  [STATE_MOT]  mot_tracker.update(frame, comp_dets)   ->  mot_tracks[]
  [STATE_SOT]  active_sot.update(frame, mot_tracks)   ->  sot_track (ID=0)
      |
      v
Visualizer.render()    video MP4  |  frames PNG  |  display cv2

State Machine MOT ↔ SOT

// STATE_MOT (defaut)
Sortie : toutes les tracks MOT
Detection : YOLO + tracker MOT (ByteTrack / BoT-SORT / ...)
Transition : clic valide -> STATE_SOT
Seuil clic : sot_click_max_dist_px (px) entre clic et track la plus proche
Clic rejete si aucune track dans le rayon (log WARNING)
MOT off : commande mot_state=0 vide les tracks, clic -> SOT Single
// STATE_SOT
Sortie : [sot_track ID=0] + mot_tracks si mot_background=true
DummySot : force MOT en fond ET masque toutes les autres tracks
Couleur SOT : magenta (255, 60, 220) BGR
Echec : sot_loss_threshold frames consecutives -> STATE_MOT
Derniere bbox affichee pendant les frames de grace (miss)
SOT Single : tracker_sot_single si MOT desactive (ex. SAM2 point-only)
Transitions d'etat
STATE_MOT
->
STATE_SOT
Clic valide + track dans rayon sot_click_max_dist_px (ou MOT off). _activate_sot() choisit tracker_sot (MOT actif) ou tracker_sot_single (MOT off).
STATE_SOT
->
STATE_MOT
sot_loss_threshold frames d'echec consecutifs (ok=False). Le SOT est reinitialise (reset()), les tracks MOT reprennent.
any
->
STATE_MOT
Commande mot_state=0 : annule le SOT en cours, vide les tracks MOT. Commande mot_state=1 : reactiver le MOT (tracks reprennent a la prochaine detection).

Format cmd_send.txt (mode command)

Structure du fichier
# Les lignes commencent par # sont des commentaires (ignores) # Deux types de lignes actives : # --- Controle MOT (3 champs) --- frame_emit,frame_real,mot_state # mot_state 0 = desactiver MOT | mot_state 1 = reactiver MOT 0,0,0 # exemple : desactiver le MOT des la frame 0 200,200,1 # exemple : reactiver le MOT a la frame 200 # --- Clic SOT (4 champs) --- frame_emit,frame_click,x,y # frame_emit = frame courante ou la commande est emise # frame_click = frame ou le clic a ete fait (peut etre anterieur -> reprojection) # x, y = coordonnees pixel du clic 265,263,646,193 # clic emis frame 265, effectue frame 263, position (646,193) 358,356,664,193 # second clic (retour SOT apres perte)
Champs communs
frame_emitFrame courante (traitement). Commande active si frame_emit <= frame_id < frame_emit + command_delta.
frame_real/clickFrame de reference du clic (peut etre anterieure). Si delta > 0, reprojection LDV ou ORB appliquee.
Reprojection du clic
Priorite 1LDV disponible (azimut/elevation) -> homographie inertielle H = K*R*K^-1
Priorite 2frame_click = frame_id-1 + H_dets dispo -> perspectiveTransform()
Priorite 3homography_method_image = orb|ecc -> calcul ORB/ECC entre frame_ref et frame_cur
FallbackCoordonnees brutes (aucune reprojection)
